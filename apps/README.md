
## Инструкция по запуску приложения temperature-api

1. Клонировать проект architecture-warmhouse на локальную машину/сервер в виртуальное окружение linux/ubuntu, проект находится по ссылке https://github.com/Ellina-Zapara/architecture-warmhouse

2. Если у вас установлена операционная система Windows, предварительно должна быть включена надстройка  (Настройки→ Система→ Подсистема Windows для Linux)
и выполнена установка подсистемы Windows для Linux (WSL), описание установки здесь
 https://learn.microsoft.com/ru-ru/windows/wsl/install 

3. Открыть PowerShell на диске, где развернуто виртуальное окружение (по умолчанию диск C). Или воспользоваться командной строкой Win11, где есть возможность открыть консоль Ubuntu.

Запустить команду, проверить установку подсистемы Linux
Команда wsl --list --verbose выводит подробный список всех установленных дистрибутивов Linux в WSL с их текущим состоянием и версией подсистемы. 
Выполнить команду wsl -d Ubuntu в консоли, переходим в виртуальное окружение Ubuntu.
(Выход из виртуального окружения команда exit)

4. Перейди в директорию с клонированным проектом в виртуальном окружении.

Команда cd /home/нужная_папка

XXX_123@UnknownUser:~$ cd /home/XXX_123/architecture-warmhouse

5. Проверь, что ты являешься пользователем docker, включен в эту группу

Команда:

groups

Если не включен, то нужно выполнить включение твоего пользователя в группу docker
Выполни в терминале WSL (под своим пользователем, не под root):

sudo usermod -aG docker $USER

После этой команды обязательно нужно перезапустить WSL, иначе изменения не применятся.

XXX_123@UnknownUser:/mnt/d$ sudo usermod -aG docker $USER
[sudo: authenticate] Password: Ввести пароль для root

Далее команда exit  //выход из wsl

Полностью перезапусти WSL
В PowerShell (не внутри WSL!) выполни:

wsl —shutdown

Затем снова зайди:

wsl -d Ubuntu

Проверь, что ты в группе docker:
groups

Должно быть так:

XXX_123 adm cdrom sudo dip plugdev users docker

Теперь можно запускать docker, выполни команду из директории проекта, где размещен файл docker-compose.yml:

docker compose up --build 

Если ошибок нет, то приложение запустится по указанному порту в docker-compose файле. В нашем случае 8000

Вставить в браузер http://localhost:8000 , при переходе откроется форма авторизации.

## Тестирование через веб-интерфейс.

1. Зайти в веб-приложение по ссылке http://localhost:8000

2. Откроется окно авторизации, ввести логин user1, ввести пароль user1

3. Чтобы получить текущую температуру в нужной локации, надо ввести локацию в форму 1 и нажать кнопку «Запросить температуру» 

	[Скриншот](apps/docs/Scrins/Запрос температуры по локации.png).

	По умолчанию стоит значение Living Room.  На данном тестовом режиме доступно 3 локации (вводить вручную). 
	{1: "Living Room", 2: "Bedroom", 3: "Kitchen"}

4. Регистрация нового устройства доступна во второй форме. Можно указывать любой номер и любую локацию, но только из возможного типа устройств.
 Для тестового режима доступно 3 типа устройств: датчик температуры, шлюз, исполнительное устройство.
 Нельзя зарегистрировать повторно устройство с одинаковым названием. Название локации может быть любым и неограничено 3-мя тестовыми записями.
 
	[Скриншот](apps/docs/Scrins/Регистрация устройства.png)
 
5. Получить список всех зарегистрированных устройств можно в третьей форме, нажать на кнопку «Обновить список».

	[Скриншот](apps/docs/Scrins/Список устройств.png)

6. Выйти из системы по нажатию кнопки «Выйти».
